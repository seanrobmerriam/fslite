# Release 0.1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare and open a release pull request for `fslite-command 0.1.1` and `fslite 0.1.1` without publishing, tagging, or creating a GitHub release.

**Architecture:** Patch only the two affected package manifests and let Cargo regenerate their lockfile package entries. Keep every unchanged workspace crate at `0.1.0`, require `fslite-command 0.1.1` from the CLI, then validate the exact package graph and publishable command crate before opening a draft PR.

**Tech Stack:** Rust 2024, Cargo workspace, crates.io packaging, Git, GitHub CLI.

## Global Constraints

- `fslite-command` and `fslite` become exactly `0.1.1`.
- The `fslite` dependency on `fslite-command` becomes exactly `version = "0.1.1"` while retaining its local `path`.
- `fslite-core`, `fslite-sqlite`, `fslite-server`, and `fslite-conformance` stay at `0.1.0`.
- Do not publish to crates.io, create a tag, or create a GitHub release.
- Open the pull request against `main` from `codex/release-0.1.1`.

### Task 1: Bump the Affected Package Graph

**Files:**
- Modify: `crates/fslite-command/Cargo.toml`
- Modify: `crates/fslite-cli/Cargo.toml`
- Modify: `Cargo.lock`

**Interfaces:**
- Consumes: the existing workspace package graph at version `0.1.0`.
- Produces: `fslite-command 0.1.1`, `fslite 0.1.1`, and a CLI dependency floor of `fslite-command 0.1.1`.

- [ ] **Step 1: Verify the release assertions fail before editing**

Run:

```bash
cargo pkgid -p fslite-command
cargo pkgid -p fslite
rg -n 'fslite-command = .*version = "0.1.1"' crates/fslite-cli/Cargo.toml
```

Expected: both package IDs end in `@0.1.0`, and the `rg` command finds no
matching `0.1.1` dependency.

- [ ] **Step 2: Apply the minimal manifest edits**

Change `crates/fslite-command/Cargo.toml`:

```toml
[package]
name = "fslite-command"
version = "0.1.1"
```

Change `crates/fslite-cli/Cargo.toml`:

```toml
[package]
name = "fslite"
version = "0.1.1"
```

and:

```toml
fslite-command = { path = "../fslite-command", version = "0.1.1" }
```

- [ ] **Step 3: Regenerate only Cargo's package-version lock entries**

Run:

```bash
cargo check --workspace --all-features
git diff -- Cargo.lock
```

Expected: the lockfile changes only the `fslite-command` and `fslite`
workspace package versions from `0.1.0` to `0.1.1`; third-party dependency
versions and checksums remain unchanged.

- [ ] **Step 4: Verify the release assertions now pass**

Run:

```bash
cargo pkgid -p fslite-command
cargo pkgid -p fslite
rg -n 'fslite-command = .*version = "0.1.1"' crates/fslite-cli/Cargo.toml
```

Expected: package IDs end in `fslite-command@0.1.1` and `fslite@0.1.1`, and
the dependency line is reported once.

- [ ] **Step 5: Prove unchanged crates remain at 0.1.0**

Run:

```bash
cargo pkgid -p fslite-core
cargo pkgid -p fslite-sqlite
cargo pkgid -p fslite-server
cargo pkgid -p fslite-conformance
```

Expected: all four package IDs end in `@0.1.0`.

- [ ] **Step 6: Commit the version graph**

```bash
git add crates/fslite-command/Cargo.toml crates/fslite-cli/Cargo.toml Cargo.lock
git commit -m "release: prepare fslite 0.1.1"
```
